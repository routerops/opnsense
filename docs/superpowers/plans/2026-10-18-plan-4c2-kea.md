## Review Focus

- A reservation `hw_address` in upper case against a stored lower-case one: expect `changed=0` if OPNsense stores it as sent, or an update on every run if it normalises; Task 4 reruns with `02:00:00:00:60:0A` vs `02:00:00:00:60:0a` and records which.
- A general save while subnets have `option_data_autocollect` on: expect their `option_data.routers` to change without a write by the caller; Task 1 (b) records it, and since no entry sends `option_data.*`, a rerun after such a save stays `changed=0` (Task 3 Step 3).
- A reservation lookup when the same MAC is reserved in two subnets: expect two items, kept apart by the composite lookup `[subnet, hw_address]` (Task 4 adds the second subnet's reservation with the same MAC).
- The apply with Kea disabled: expect `ok`, so `changed` stays true and the run passes (Task 1 records it; if it answers `failed`, the area note says so and the tests drop the apply).
- A delete of a subnet still in use, through `item`: expect `failed`, `not changed`, and the message naming the reservation (scenario).
