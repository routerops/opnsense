## Review Focus

- Two children with the same description under different connections: expect the lookup to fail with "matches several items", never to update the wrong one (Task 4 asserts it).
- A connection rerun while `get` returns the computed `local_ts`, `remote_ts`, `uuid` and `org_uuid`: expect `changed=0`, because only sent fields are compared (Task 7 reruns the connection after its child is added).
- A pre-shared key whose `Key` changed on the router: expect a change with the diff showing the field masked, never the key (Task 5 asserts the diff text).
- A VTI search on a router with legacy VTIs: expect the legacy rows to be ignored for lookup and purge; no test (the VM has no legacy tunnel), the note says so.
- An apply with IPsec disabled: expect `ok` without starting strongSwan (Task 1 records it; every test's apply proves it).
